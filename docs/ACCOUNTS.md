# Accounts and data

## Accounts

- **Codex:** Discovers `~/.codex/auth.json`, `~/.codex/accounts/*.auth.json`, the native registry, and `~/.codex-swap/accounts/*.auth.json`. Deduplicates by workspace and user. Reads live usage and credits. The arrow switches the file-based CLI sign-in; restart running clients to reload it. Keychain-only Codex credentials are not currently supported.
- **Claude:** Detects the Claude Code account and reads five-hour, weekly, and model-specific allowances. Uses the existing macOS credential or `.credentials.json`. Save each sign-in from the Claude menu to enable switching; saved credentials stay in Keychain. Switching updates Claude Code's OAuth credential and account metadata, preserving unrelated settings and MCP credentials. Claude Desktop/browser sign-ins are separate.
- **Z.ai / BigModel:** Detects keys in Claude Code's `settings.json` when its base URL is an allowlisted Z.ai endpoint, or `ZAI_API_KEY` in the app's environment. Connect a Coding Plan key privately in Settings. Switching saved keys updates an **existing** Z.ai configuration in Claude Code. ZCode desktop's own login must be changed in ZCode; this app does not read its private browser storage. An installed ZCode app without credentials does not add a provider row.

- **Gemini:** Reads the active Gemini CLI OAuth sign-in from `~/.gemini/oauth_creds.json` or the CLI's `gemini-cli-oauth` Keychain item. `GEMINI_CLI_HOME` overrides the home containing `.gemini`. Old account names without credentials, API-key mode, Vertex mode, and the CLI's encrypted fallback store are not supported. Google userinfo verifies known account identities before fetching quotas. OAuth refresh and account changes stay in Gemini CLI. `GOOGLE_CLOUD_PROJECT` or `GOOGLE_CLOUD_PROJECT_ID` can supply the Code Assist project when inherited by the app.
- **Antigravity:** Finds the installed `agy` CLI through PATH, `~/.local/bin`, `~/bin`, or standard Homebrew locations. `ANTIGRAVITY_CLI_PATH` can select an absolute executable path. Requires version 1.1.11 or later, and a working CLI sign-in. Runs the read-only `/usage` command in JSON mode; it does not send a model prompt. Shows only reported quota buckets. The report omits account and plan identity, so the app labels it Local CLI and does not infer a paid plan or offer switching.

- **GitHub Copilot:** Reads Copilot-specific `hosts.json`/`apps.json` under `~/.config/github-copilot`, public GitHub entries in `~/.copilot/config.json`, the `copilot-cli` Keychain service, or `COPILOT_GITHUB_TOKEN`. It does not reuse `gh`, `GH_TOKEN`, `GITHUB_TOKEN`, or enterprise-host credentials. Request quotas and unlimited pools are shown when reported. New AI-credit plans can report usage without a per-seat allowance; the tracker leaves that limit unknown.
- **Cursor:** Reads `cursorAuth/accessToken` from the editor’s `state.vscdb`, or `~/.config/cursor/auth.json` when the editor has no token. It derives a session from that local token and verifies its subject with Cursor. It never imports browser cookies or silently switches to a second account after a rejected request. Legacy model pools and unified weekly pools stay separate. Unified accounts with unavailable weekly data stay unknown.
- **Kimi:** Supports global (`api.kimi.ai`) and China (`api.kimi.com`) subscriptions. Reads the official region-scoped OAuth files under `~/.kimi-code/credentials`, provider keys in OpenCode or Claude Code, or `KIMI_CODE_API_KEY` with `KIMI_CODE_BASE_URL`. `KIMI_CODE_HOME` is respected. Unrecognized endpoint overrides disable OAuth-file discovery. The app does not refresh OAuth tokens. A key can also be connected in Settings with its region. Only returned five-hour, weekly, or monthly windows appear; newer plans need not have a weekly allowance.
- **MiniMax:** Reads subscription keys configured for MiniMax Coding Plan in OpenCode or Claude Code, `MINIMAX_CODING_API_KEY`, or `MINIMAX_CN_API_KEY`. `MINIMAX_API_KEY` is accepted only with the coding-key prefix. Standard `sk-api-` keys are excluded. Settings supports global and China subscription keys. The M Plan endpoint provides shared remaining percentages, older count allowances, or service windows. Missing counts never become a guessed limit.
- **Devin / Windsurf:** Reads `windsurf.settings.cachedPlanInfo` from the local Devin, Windsurf, or Windsurf Next editor database. A local cache does not validate the current sign-in. Cache-only entries are therefore hidden from the tracker until authenticated usage support is available. A desktop login without this cache has no supported usage reading. Live Devin web quotas and browser sessions are not currently imported.
- **Kiro:** Reads the CLI token and regional profile ARN from `~/Library/Application Support/kiro-cli/data.sqlite3` or `KIRO_DATA_DIR`. Supports the US East and Frankfurt service endpoints. Reports explicit plan, trial, and enabled overage credits. When bonus spend cannot be separated from the plan, it shows reported total usage with an unknown combined limit. Kiro IDE-only sign-ins are not yet supported.
- **OpenCode Go:** Reads the `opencode-go` entry in `~/.local/share/opencode/auth.json`, `OPENCODE_API_KEY`, or a key connected in Settings. Shows the usage endpoint’s five-hour, weekly, and monthly percentages without estimating dollar allowances from model prices. OpenCode’s own locally calculated costs are not subscription spend.

`XDG_CONFIG_HOME` and `XDG_DATA_HOME` are respected for supported CLI files. Apps opened by Finder may not inherit shell environment variables. Connected keys are stored in Keychain and appear in the tracker; connecting one does not change another coding app’s active key. Provider APIs that omit account identity can show the same subscription more than once when it has multiple distinct keys.

Google ended Gemini CLI OAuth support for individual Free, AI Pro, and Ultra plans in June 2026. Use Antigravity for those plans. Existing eligible Code Assist accounts use the Gemini integration. Neither integration promises a fixed allowance or infers a plan from quota size.

Discovery runs privately. Provider sections, account rows, and notch readouts appear only after an authenticated usage request succeeds in the current app session. Saved credentials, installed apps, old metadata, and disk caches alone cannot make an account visible. Failed checks hide the account until a later check succeeds. If a provider has no verified accounts, its entire section disappears. Settings keeps the Add account catalog available. Antigravity becomes active only after a successful usage report. Installed apps alone are not evidence of a paid subscription. A plan name reflects the provider's reported plan, not billing verification.

Bars show remaining allowance for each provider window, including Codex plans whose primary window is weekly. Credits stay labeled credits. Weekly dollar spend appears only if the provider supplies an explicitly weekly monetary amount, currency, and units; the Codex/Claude responses tested locally do not. Monthly extra usage is never relabeled as weekly spend.

## Refresh and switching

Usage refreshes every five minutes and after wake. Manual refresh has a one-minute per-account floor; HTTP 429 adds a 15-minute cooldown. Cached/expired readings are marked. A passed reset time never silently becomes 100% available. HTTP 401/403 requires the provider's own sign-in. The app does not rotate OAuth refresh tokens in the background.

Google readings are revalidated on refresh and are not persisted in the usage cache. Antigravity's CLI owns its token refresh. Its subprocess runs in a private temporary directory with browser launchers blocked and automatic CLI updates disabled. Output is capped at 1 MiB with a 45-second deadline. Cleanup stops its process group and same-user descendants carrying a unique probe marker, including detached MCP servers. Children that discard that marker cannot be identified by this fallback. Your independently running CLI sessions are not selected for cleanup.

Switching verifies the target with the provider, preserves refreshed outgoing credentials, uses private backups and atomic file replacement, and rejects changed files or symlinks. Codex registry and legacy swap state stay aligned. This changes local sign-in files, not running agent sessions. Restart those clients afterward; their token writers do not share this app's lock.

**Add account** opens a key form or the provider’s own sign-in. For Codex and Claude, the outgoing account is saved before opening login. Switching for all additional providers stays in their own client. No login is triggered automatically.


## Local data

Direct HTTPS requests are limited to `chatgpt.com`, `api.anthropic.com`, `api.z.ai`, `open.bigmodel.cn`, `cloudcode-pa.googleapis.com`, `www.googleapis.com`, `api.github.com`, `cursor.com`, `api.kimi.com`, `api.kimi.ai`, `www.minimax.io`, `www.minimax.cn`, `opencode.ai`, `codewhisperer.us-east-1.amazonaws.com`, and `q.eu-central-1.amazonaws.com`. Credential-bearing requests reject redirects. Antigravity's installed CLI uses its own network, authentication, and MCP configuration; the app's HTTP allowlist does not control that subprocess. No analytics, backend, proxy, or browser-cookie extraction. Secrets never appear in arguments or logs. Metadata, usage, and backups live under `~/Library/Application Support/SubTracker` with private file permissions; saved Claude credentials and connected subscription keys use macOS Keychain. Authentication backups contain secrets and must remain private.

To remove: quit, disable Open at login, and remove `~/Applications/Sub Tracker.app`. Remove the support directory and Keychain items under `com.sagar.subtracker.accounts` to discard saved data. Removing the app does not sign out providers.
